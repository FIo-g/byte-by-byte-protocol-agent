2026-11-18 KST에 Codex가 macOS arm64의 Docker Desktop에서 N10 병합본(`f1b1d84`)의 입력 두 파일을 검증했다. N05 이미지 `byte-by-byte-n05:rea6.8.0`의 linux/amd64 환경을 사용했다.

## Codex 자동 검증

- 입력 두 파일의 SHA-256을 실행 전후에 비교했고 모두 일치했다. `tcpdump -nn -r experiment/n10/sessions.pcap`으로 92패킷, SYN 6개, SYN-ACK 6개, FIN 12개, RST 0개를 확인했다.
- 네트워크가 격리된 컨테이너에서 서버를 서로 다른 임시 루프백 포트로 3회 기동했다. 매번 N10 원본 클라이언트로 캡처 당시의 정상 세션 6개를 실행해 비공개 기준 출력과 비교했다. 총 18회 모두 일치했고, 각 실행 후 서버 종료와 포트 접속 거부를 확인했다.
- PR #11의 `63cd274`에서는 `node scripts/rea-smoke.mjs --rea-only experiment/n10/n10-server /results/pr11-rea.json`을 실행했다. REA 6.8.0에서 Ghidra 진단과 입력 해시 확인이 통과했다. 모델 요청은 0회였다.
- 같은 커밋의 `n09-prepare.mjs`로 E1 A/B 입력을 각각 준비했다. 양쪽 PCAP과 공통 프롬프트 해시가 일치했고 B의 바이너리 해시도 위 표와 일치했다. 두 준비 작업에서 모델 요청과 서버 질의는 0회였다.

## E1 실패 확인

E1에서 이상 결과가 나오면 같은 서버 해시와 실행 조건에서 원본 클라이언트를 다시 실행한다. 원본도 실패하면 서버·환경 로그를 확인하고, 원본만 통과하면 복원 명세와 생성 클라이언트의 전송·수신 기록을 확인한다. 이번 실행은 정상 경로 기준선이며 본 실험의 개별 실패 판정은 실험 결과가 나온 뒤에 기록한다.

로컬 요약은 `runs/n11-n14/20261118.rgeciV/n14-baseline.json`에 있다. 원본 클라이언트와 기준 출력은 비공개 위치에서 관리한다.
