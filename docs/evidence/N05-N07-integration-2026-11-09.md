# N05·N06·N07 통합 재현 기록 — 2026-11-09

정의종의 요청으로 Codex가 **정의종의 Windows x86-64 호스트와 Docker Linux 컨테이너**에서 실행했다. AI 실행 기록이며 정의종 본인 확인이나 실제 모델 연동을 대신하지 않는다. 공개 연습 자료만 사용했고 본 실험 점수는 아니다.

## 확인 결과

| 검증 | 코드와 결과 |
| --- | --- |
| N05 모의 테스트 | `0ac1666`, 25/25 통과 |
| N07 기존 모의 테스트 | `0ac1666`, 19/19 통과 |
| N06 서버·클라이언트 재빌드 | GCC 13.3.0, 경고 없이 성공. 두 바이너리 모두 기존 공개 해시와 일치 |
| N06 → N07 실제 TCP 평가 | `0ac1666`, 21/21 pass, 서버 종료 확인 |
| N06 → N05 실제 REA 단독 | `0ac1666`, 성공. 입력 해시와 REA subject 해시 일치, Ghidra 출처 확인 |
| N06 PCAP 재생성 | `0ac1666`, 정상 5세션, 50패킷 / SYN 5 / FIN 10. 서버·tcpdump 종료 확인 |
| N07 제한 시간 수정 후 | `cac9e9b`, 모의 21/21 및 실제 N06 21/21 pass, 서버 종료 확인 |

표의 실제 실행 JSON은 모두 `code_dirty: false`다. Git worktree의 메타데이터를 읽기 전용으로 `/git`에 마운트하고 `GIT_DIR`와 `GIT_WORK_TREE`를 지정했다. Git 정보를 기록하지 못한 최초 탐색 실행은 로컬에 보존하되 이 표의 근거에서 제외했다.

입력 해시:

- N06 서버, 16,928바이트: `d6cd6d971030e34601c2953fd71eceef7ac4fab0c8f0dde285a51a04ab040067`
- N06 클라이언트, 16,792바이트: `0ad87f81537ee489e4bb0cc80eb6878e3353f6b4d6f6fab073e4581cd23588cf`
- 기존 공개 PCAP: `e9b5650cd8aab5f0480a1b99740af67e7713f5083f5a58c0acaa5535207bd698`
- 이번 재생성 PCAP: `dd8133e8350cf700c2814603679758b476bc90f962bfea8427a89b360ae2a56d` (4,310바이트). 캡처 시각과 포트가 달라 원본과 해시가 다른 것은 정상이다.

REA `binary_overview`의 관찰 결과는 함수 인벤토리 79, 정의된 문자열 119, 세그먼트 33이다. 프로토콜을 모델이 복원했다는 뜻은 아니다. `doctor.healthy: true`이며 다른 엔진·신원 설치 등 정보성 검사로 `environment_healthy: false`다.

## 통합과 수정

PR [#1](https://github.com/jeonguijong67-hub/byte-by-byte-protocol-agent/pull/1), [#2](https://github.com/jeonguijong67-hub/byte-by-byte-protocol-agent/pull/2), [#3](https://github.com/jeonguijong67-hub/byte-by-byte-protocol-agent/pull/3)을 의존 순서대로 병합했다. N05는 기반 코드 병합이며 작업 완료 표시는 아니다. 태형의 본인 실행 확인은 팀 노션의 11월 9일 기록을 근거로 했고, 이번 AI 재현과 구분한다.

N07은 연결 뒤 케이스 전체에 시간 제한을 적용한다고 설명하지만, 기존 코드는 조각 사이 대기와 전송에 남은 시간을 적용하지 않았다. 수정본은 대기를 남은 시간으로 제한하고 매 전송·쓰기 종료·수신에 남은 시간을 적용한다. 연결 시도 시간 제한은 별도다.

회귀 테스트 두 개를 추가했다. 실제 소켓으로 100ms 제한과 800ms 조각 대기를 조합하고, 가짜 시계로 느린 전송이 남은 예산만 쓰는지 확인한다. 수정 뒤 테스트는 21/21, N06 실제 평가도 21/21이다.
